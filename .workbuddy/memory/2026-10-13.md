## Redis 接入（SSE Pub/Sub + 心跳缓存 + 配置副本）

## 修复 ECharts 动态加载报错

报错：`TypeError: Cannot read properties of undefined (reading 'install')` at `use([...])`。

**根因（两个 bug）**：
1. `CanvasRenderer` 从 `echarts/charts` 解构——实际在 `echarts/renderers`！解构得到 undefined，`use([undefined,...])` 报 install 错误。
2. 动态 `import('echarts/components')` 聚合入口在 Vite 预构建后命名导出可能丢失（dev 模式 `?v=hash` 尤甚）。

**修复方案**：拆分 setup 文件 + 静态 import。
- `src/plugins/echarts-setup.js`（新）：静态 import `echarts/core`(use)、`echarts/renderers`(CanvasRenderer)、`echarts/charts`(LineChart/PieChart)、`echarts/components`(Grid/Legend/Title/Tooltip)、`vue-echarts`(VChart)；静态 use 注册；export default VChart。
- `src/plugins/echarts.js`（改）：简化为 `defineAsyncComponent` + `await import('./echarts-setup.js')`。setup 文件形成独立异步 chunk，ECharts 核心首屏不加载。

**关键优势**：静态 import 让 Vite 正确分析 ESM 导出（不依赖动态 import 预构建），同时 `import('./echarts-setup.js')` 仍保持异步 chunk 分包。

**构建验证**：vite build 通过。echarts.js 0.67kB（极轻）、echarts-setup.js 506kB（独立异步 chunk）、Dashboard 6kB / ApiStats 10kB（不含 ECharts）。

**⚠️ 关键踩坑**：
1. **EMQX 有两套认证体系，不能混用**：① MQTT 客户端认证（设备/服务端连 broker，用户名+密码在控制台「认证」里建）；② REST API 凭据（appid+app-secret，Basic Auth）。用户给的 `admin/Password1234` 是**控制台登录账号**，不是 MQTT 客户端凭据；`appid/app-secret` 才是 REST API 凭据。实测：MQTT 客户端连接返回 `Bad username or password` / `Not authorized`（1903/1883 端口都可达），但 **REST API publish 返回 HTTP 202 完全可用**。
2. **EMQX REST API 的 publish 字段名是 `payload_encoding` 不是 `encoding`**——写错返回 400 `unmatched: clientid,payload_encoding`（`validation_error`）。

4. **端口 1883 用 `mqtt://` 不是 `mqtts://`**：原来我按 8883 写死了 mqtts，改配置时忘了改协议。现加 `MQTT_TLS` 开关自动选协议。`rejectUnauthorized` 也要跟着 TLS 走（明文端口传 true 会出问题）。
5. **REST API 与 broker 是两个地址**：broker 是 IP（129.204.31.17），REST API 是域名（i07bb631.ala...emqxsl.cn）。原来用 `${MQTT_HOST}:8443` 拼 API 地址是错的，现拆成独立 `MQTT_API_URL`。

1. **直接原因**：后端(3000)和前端(5173)服务都没运行（之前会话中手动终止了后台任务）。两个端口 Connection refused。
2. **代理干扰**：系统环境有 `HTTP_PROXY=http://127.0.0.1:55285`，curl/浏览器访问 localhost 走了代理返回 502，掩盖了"服务未运行"的真相。需 `--noproxy '*'` 或设 `NO_PROXY=localhost,127.0.0.1` 才能看到真实的 Connection refused。
3. **代码隐患**：路由守卫 `router.beforeEach` 中 `authApi.me()` 使用默认 15s 超时。后端不可达时，页面空白等待 15 秒才跳登录；且 catch 块无差别 `clearSession()`，后端暂时不可达也会强制登出（token 没过期不应清除）。

**改动**：
- `src/utils/api.js`：`authApi.me` 加可选 options 参数透传（`me: (options) => request.get('/auth/me', null, options)`）。
- `src/router/index.js`：路由守卫改用 `authApi.me({ timeout: 5000 })`（5s 快超时）；catch 块区分 401（token 失效→清除会话跳登录）与网络错误（后端暂时不可达→保留会话用缓存数据继续渲染，后续 401 由 request.js 自动处理）。

**处理**：重启后端（端口 3000）和前端（Vite 自动选了 5174，因 5173 瞬态占用），设 `NO_PROXY=localhost,127.0.0.1` 绕过系统代理。验证全链路正常（后端 footer → 前端 HTML → Vite 代理 /api → 登录接口 code:0）。
