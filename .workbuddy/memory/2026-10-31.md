# 2026-10-31 — 移动端 UI 动画优化

## 目标
为 `mobile/`（uni-app H5）建立统一动效层，覆盖列表、弹层、详情页、登录/个人页，并修复验证时发现的两处层级问题。

## 改动
- 新增 `mobile/src/styles/animations.css`（main.js 引入）：
  - 关键帧：fade/rise/drop/pop/sheet-up/mask-in/panel-down/bar-grow/badge-pop/stripes。
  - 工具类：`anim-page`（仅 opacity，避免给 fixed 子元素制造包含块）、`anim-rise`、`anim-drop`、`anim-pop`、`anim-sheet`、`anim-mask`、`anim-panel`、`anim-bar`、`anim-badge`。
  - 全部用 `animation-fill-mode: backwards`（不是 both）：动画结束后不残留 transform，`:active` 缩放才生效。
  - 点按反馈 `tap`/`tap-sm` + `uni-button:active` + `.uni-tabbar__item:active`。
  - 输入聚焦 `.input:focus-within`；`prefers-reduced-motion: reduce` 全局降级。
  - `uni-toast`/`uni-modal` 提到 z-index 1100，保证弹层内表单校验提示不被遮罩挡住。
- 新增 `mobile/src/utils/motion.js` 的 `useCountUp`：概览/告警统计数字滚动。
  - ⚠️ 用 setInterval + performance.now，不用 rAF：rAF 在后台标签页/内嵌 WebView 会挂起，数字会永远停在 `-`；定时器按真实时间算进度，最终必到目标值。
- 逐页应用：概览（分区错峰、数字滚动、柱状 scaleY 生长、气泡/徽标弹出）；设备/产品/告警/公告/固件/OTA 列表（卡片 40ms 错峰入场、FAB pop）；底部弹层（遮罩淡入 + 面板上滑）；设备详情（hero 下移入场、5 页签切换重播、指标柱错峰、时间轴错峰）；登录（hero/panel 入场、tab 下划线 scaleX）；我的/服务器/改密码/详情页入场。
- 层级修复：所有 `.modal`/`.mask` 底部弹层 z-index 100/无 → 1000（uni-tabbar 为 998）；`product/product.vue` 的 `.mask` 原本**完全没有样式**（静态 block，不是遮罩），补齐 fixed overlay + sheet 滚动。
- 固件上传进度改为真实进度条（宽度过渡）。

## 验证
- `npm run build:h5` 通过；产物 `index-*.css` 含全部关键帧各 1 次，scoped CSS 里 `anim-stripes` 未被重命名。
- 浏览器实测（IAB，420×900）：登录 → 概览 → 设备/产品/告警/公告/固件/OTA/详情/我的；`window.__errs` 全程为空；卡片 delay 0/0.04/0.08…、时间轴 0/0.035/0.07/0.105、指标柱 0/0.018/0.036 均符合预期。
- ⚠️ 本机/IAB 报告 `prefers-reduced-motion: reduce`，所以实际页面动画会被全局降级（duration 1ms、delay 0）。验证动态效果需在 DevTools 里删掉该 media rule（遍历 styleSheets 删除 conditionText 含 prefers-reduced-motion 的规则），或系统关闭“减少动态效果”。这是预期行为，不是 bug。
- IAB 的 Playwright 点击对部分 `uni-button` 会超时，坐标 `tab.cua.click` 可用；`uni-input` 的 placeholder 是内部 div 而非 input 属性，填值用 `uni-input:has-text(...) input`。

# 2026-10-31 — 控制指令下行报文对齐 MQTT.md

## 改动
- 下行报文从 `{type, cmd_id, command, params, timestamp}` 改为 `{type:'control', timestamp, data:{action, ...params}}`；`cmd_id` 不再下发，只保留在 `device_control_logs` 用于日志/回执关联。
- `server/services/device-control.js`：`sendCommand` 接收 `action`（兼容旧 `command`），参数必须是 JSON 对象并展开进 `data`；`action` 为保留字段。回执可不带 `cmd_id`：按 topic 解析设备（id 或 SN），匹配该设备最早一条 `sent/delivered` 指令；带 `cmd_id` 的旧回执仍优先精确匹配。
- `server/db/init.js`：建表列 `command` → `action`，启动时 `ALTER TABLE ... RENAME COLUMN` 幂等迁移；`server/routes/devices.js` 请求体 `{action, params}`、timeline SQL 同步。
- 管理端 `src/views/Devices.vue`：动作模板/`ctrl.action`/历史 `c.action`；新增「自定义动作」动作名输入。移动端 `detail.vue` 同步（`actionOptions`/`currentAction`/`c.action` + 自定义动作名）。
- 文档：MQTT.md §4.2 补 data 展开与 `control_ack` 说明；API.md、INTEGRATION.md、ARCHITECTURE.md、CHANGELOG.md 同步；fnos-app 三个服务端源码副本已同步（内置 public/admin 静态产物未重新打包）。

## 验证（真实 MQTT 抓包）
- 下行实测：`{"type":"control","timestamp":"2026-10-31T11:17:21.569Z","data":{"action":"reboot","delay":3}}`，确认无 `cmd_id`/`command`/`params` 顶层字段，`data.delay` 已展开。
- 无 `cmd_id` 回执 `{type:'control_ack',data:{code:0,...}}` 成功把最新指令推进为 `success`，`action/acked_at` 正确；旧 API `{command:'sync_time'}` 与带 `cmd_id` 的回执同样通过。

## 后续：管理端「指令为空」排查
- 根因不是前端表单：`.env.development` 的 `VITE_PROXY_TARGET` 指向 NAS `http://192.168.0.127:3000`，NAS 后端仍在跑旧代码（只读 `command`），新前端只发 `action` → 旧后端报「指令不能为空」。
- 处理：管理端与移动端下发请求同时带 `action` + `command`（新后端优先 `action`，旧后端读 `command`），过渡期两边都能用；要下发新格式仍需重新部署并重启 NAS 后端。
- 预设动作扩充为 7 个（两端一致）：重启设备、同步时间、查询状态、开关控制（switch）、设置上报间隔（set_config）、恢复出厂、自定义动作。
