## 新增：设备侧固件订阅接口

### 需求
设备通过 HTTP 请求服务端获取固件信息（固件直链、版本号、状态等）；设备页面可一键生成订阅链接。

### 后端（新增 `server/routes/subscribe.js`，挂载 `/api/subscribe`）
- `GET /:key` 设备订阅：返回 `device / update_available / latest / available_versions / compat`。`:key` 同时支持设备 ID 与 DeviceName(SN)。
- `GET /:key/link` 管理端生成订阅链接：返回 `url / url_template / token / require_token / latest / sample.curl`。
- `GET /:key/download` 带鉴权下载，`?version=` 可指定版本，下发文件名统一 ASCII（`<FW-ID>-<版本>.bin`）。
- 鉴权：`HMAC-SHA256(SUBSCRIBE_SECRET, 'device:'+id)` 前 16 位，走 `?token=`；`SUBSCRIBE_REQUIRE_TOKEN=false` 可关闭。
- 基础地址解析顺序：`?base=` → `SUBSCRIBE_BASE_URL` → 请求头 Host，保证反代/内网穿透下直链可用。
- 版本比较自实现（去 v 前缀 + 逐段数字比较），设备版本高于库内版本时不降级。
- **设备侧接口返回真实 HTTP 状态码（403/404）**，这是与项目其余接口（HTTP 200 + body code）的有意区别，便于嵌入式端分支。

### 前端
- `utils/api.js` 新增 `subscribeApi`；新增 `utils/clipboard.js`（`copyText`，HTTP 环境降级 execCommand）；`icons.js` 新增 `Link`、`CopyDocument`。
- `Devices.vue` 操作列加「订阅」按钮 + 订阅对话框（订阅地址与复制 / token 说明 / 最新固件 / 接入示例 / **设备端真实响应预览**）。

### 其他
- `server/db/init.js` 为 `file_path` 为空的固件生成 `demo-<id>.bin` 占位文件；只对从未设置过 `file_path` 的固件生效，避免掩盖真实文件丢失。
- ⚠️ 当前数据库已**不是**种子数据，而是用户自建数据（产品「补光灯」、设备 `led-light`、固件 `FW-20261012-495` v1.0.0）。后续调试/验证不要假设种子数据存在。

## 新增：一键启动脚本（含端口占用自动清理）

### 交付文件
- `start.bat`（Windows 双击，纯 ASCII + `chcp 65001`）、`start.sh`（重写，原文件指向不存在的 `server/server.js`、端口 3001、`cd src && npx vite`，全部失效）。
- `scripts/start.mjs`（主流程）、`scripts/stop.mjs`（释放端口）、`scripts/lib/ports.mjs`（端口/进程）、`scripts/lib/runtime.mjs`（Node 运行时 + 原生绑定自愈）。
- `package.json` 新增 `start` / `stop` / `dev:backend` / `dev:frontend`。
- `vite.config.js`：代理目标改为 `process.env.VITE_PROXY_TARGET || env.VITE_PROXY_TARGET || 默认`，使 `--api-port` 能同步到 Vite 代理（`loadEnv` 不读 `process.env`，必须显式合并）。

### 关键实现点（踩坑）
- **探测 better-sqlite3 的 ABI 必须真正 `new Database(':memory:')`**。better-sqlite3 对原生绑定是**惰性加载**，只 `require('better-sqlite3')` 不会触发原生模块装载 —— 任何 Node 版本都会「探测通过」，得到假阳性。
- Windows 端口占用：`netstat -ano` 解析 `LISTENING` 行，比对**本地地址的端口段**（`local.split(':').pop()`），不能 `endsWith(':3000')`，否则 `15173` 之类会误判。结束用 `taskkill /F /T /PID`（连带子进程，否则 Vite/`node --watch` 会残留）。
- `tasklist /FI "PID eq N" /FO CSV /NH` 拿进程名；进程正在退出的瞬间会查不到，需重试一次；查不到时退回只显示 `PID N`，不要硬编「未知进程」。
- **在 Git Bash 里直接测 `tasklist /FI ...` 是假的**：MSYS 会把 `/FI` 转成 `D:/.../PortableGit/FI` 路径。必须用 Node 的 `execFileSync` 测（脚本内部就是走它，不受影响）。
- 启动脚本杀掉后端后自身会检测到子进程退出并把前端一起收掉，因此 `npm run stop` 之后**所有端口都空闲**；此时启动脚本打印的退出码为 1（子进程被外部结束），属预期。
- 自身保护：`PROTECTED_PIDS` 含 `process.pid` / `process.ppid`，绝不误杀终端。

### 实测结论
- Node 26（ABI 147）无法加载 `node-v127` 二进制 → 脚本自动切换到 `C:\Users\ninesugar\.workbuddy\binaries\node\versions\22.22.2-6\node.exe`（ABI 127），打印诊断后正常启动。
- 端口占用自动清理：二次启动时结束前一个实例的后端 + 前端进程并重新拉起，PID 确实变化。
- `--no-kill` 只提示不结束、退出码 1；`--api-port 3100 --web-port 5200` 自定义端口下前端 `/api` 代理正确跟随到 3100。
- `npm start` → 端口就绪 → `npm run stop` 全链路通过；`start.bat --help` 参数透传正常。

## 新增：订阅接口承担设备激活与心跳

### 需求
未激活的设备通过订阅该链接后，服务端设备状态自动激活，并同时更新最后上线时间。

### 实现（`server/routes/subscribe.js`）
- 新增 `touchDeviceOnline(device, ip)`，在 `GET /:key` 的 **verifyToken 之后**调用（无效凭证零副作用）。
- 状态机：`inactive → online`（首次激活）、`offline → online`（重新上线）、`online → online`（仅刷新）、`fault → fault`（保持，不掩盖故障）。
- 时间字段语义：`active_time` **只在首次激活时写入**，之后不变；`last_online` 每次成功订阅都刷新。
- `ip` 仅在来源为非环回地址时更新（避免本机调试把 127.0.0.1 冲进档案）。
- 响应 `data.device` 新增 `account_status`（订阅前状态）、`status_changed`、`activated`、`active_time`、`last_online`。
- `GET /:key/link` 也返回 `status` / `active_time` / `last_online`，便于弹窗展示。
- 时间格式手写 `formatLocalDateTime()` 输出 `YYYY-MM-DD HH:mm:ss`，与 SQLite `datetime('now','localtime')` 保持一致。

### 前端（`src/views/Devices.vue`）
- 订阅弹窗新增「设备状态 / 激活时间 / 最后上线」行 + 未激活引导提示 + 心跳说明文案。
- `openSubscribe` 里那次真实订阅请求会触发激活，据此回填弹窗数据并 `search() + loadStats()` 刷新列表与统计，弹出「设备已自动激活，当前状态：在线」。
- 详情抽屉补「激活时间」行。

### ⚠️ 重要副作用（后续排查须知）
- **打开设备页的「订阅」弹窗本身就会激活该设备**（弹窗内会真实请求一次订阅接口用于预览响应）。测试时不要误以为「有别的设备连上来了」。

### 验证（35 项断言全过）
- inactive 首次订阅激活 + 写双时间、重复订阅 active_time 不变而 last_online 刷新、offline 恢复且保留原 active_time、fault 不被覆盖但 last_online 仍刷新、403/404 零副作用、SN 订阅同样触发激活、环回 IP 不覆盖。
- 真实设备 `led-light`（id=9）实测：`inactive` → `online`，active_time/last_online 均写入，`devices/stats` 从 `{inactive:1}` 变为 `{online:1}`。
- 前端：`vite build` 通过；无头 Chrome 渲染弹窗，成功提示「设备已自动激活，当前状态：在线」出现、0 错误提示。

## 新增：OTA 升级指令主动推送 + 结果上报 + 告警生成

### 需求
升级任务创建后主动向在线设备推送升级通知（复用订阅代码）；离线设备上线后补推；设备上报升级结果（成功/失败/进度），平台整理并创建告警。

### 架构（两层互补推送）
- **SSE 实时推送**：`GET /api/subscribe/:key/events` 长连接，任务创建时 `emit('upgrade', cmd)` 立即下发——真正主动 Push。连接表在 `server/services/push.js` 内存（单实例）。
- **订阅轮询补推**：`GET /:key` 响应新增 `pending_upgrades`，设备每次订阅捎带积压任务；离线设备上线（激活）后首次订阅即拿到——天然补推，复用订阅/激活代码。

### 后端
- 新表 `device_upgrade_jobs`（task_id/device_id/status/progress/error_msg/pushed_at/acked_at/completed_at）。
- `routes/ota.js`：
  - 创建任务时按目标设备生成 jobs；`strategy=immediate` → status 直接 `running` + SSE 推送在线设备。
  - 新增 `GET /:id/jobs`（设备级明细）、`POST /:id/push`（重新推送，`?reset_failed=1` 重置失败设备）。
  - `resolveTargetDevices`：显式 `device_names` 数组→按 SN 匹配；否则取产品全部设备。`total` 由服务端按实际设备数写。
- `routes/subscribe.js`：
  - `GET /:key` 增加 `pending_upgrades`（仅 `task.status='running'` 的 job 才下发，paused/cancelled 不下发）。
  - `GET /:key/events` SSE：hello 事件 + 补推当前积压 + 25s keep-alive 注释。
  - `POST /:key/report`：upgrading/success/failed。success→更新 `devices.firmware_version`；failed→记 `ota_fail_devices`（去重）+ 创建 `major` 告警（unhandled）。
  - `recomputeTaskStats`：done/running/failed 直接从 job 聚合（避免增量错位）；`done+failed>=total` 且 `running` 时自动 `completed`。
- token 生成在 ota.js 与 subscribe.js 各有一份 `buildSubscribeToken`（HMAC-SHA256(secret,'device:'+id) 前 16 位），保持一致。

### 前端
- `constants` 新增 `UPGRADE_JOB_STATUS`（pending/pushing/upgrading/success/failed）。
- `api.js`：`otaApi.jobs(id)`、`otaApi.push(id,params)`、`subscribeApi.report(key,data,params)`（report 第三参数包成 `{params}`，因 `request.post` 第三参数是 options）。
- `OTA.vue`：任务行新增「推送明细」按钮 → 对话框（设备级 job 表：状态/进度/失败原因/推送时间/完成时间 + 重新推送按钮）。

### ⚠️ 注意
- SSE 连接表在进程内存，**多实例部署需换 Redis Pub/Sub**（当前单实例够用）。
- 推送只针对 `task.status='running'` 的 job；paused/cancelled 任务即使设备在线也不下发。
- 创建任务时 curl 在 Git Bash 里发中文 body 会乱码导致 product_name 不匹配 → "没有可升级的设备"，必须用 Node 发请求或用文件传 body。

### 验证（44 项断言全过）
- 在线设备 SSE 收到 hello + upgrade 事件、指令含 task_id/target_version/download_url；job 状态正确分流（在线=pushing/离线=pending）；离线设备上线订阅补推拿到 pending_upgrades；上报 upgrading(30%)→job upgrading+task running=1；上报 success→job success+设备版本更新+done=1；上报 failed→job failed+ota_fail_devices 记录+major 告警生成；任务自动 completed；GET /ota/:id/jobs 返回明细。
- 前端：`vite build` 通过；无头 Chrome 渲染 OTA 推送明细对话框 10 项全部命中、0 错误提示。
