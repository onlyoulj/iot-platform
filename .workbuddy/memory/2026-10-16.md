## 新增：mobile/ uni-app 移动端（可选后端）
- ⚠️ HBuilderX 编译器版本对齐（第二轮踩坑）：本机 HBuilderX（D:\HBuilderX）自带编译器 uniapp-cli-vite 为 **2024-02 老版 `3.0.0-alpha-4000120240201002`**（编译器版本号 4.01，vue 3.3.11 + vite 4.2.1），而项目 node_modules 装最新 alpha `5030120260930001`（编译器 5.31）会混用：老编译器没有把 `vue` 重定向到 uni 分叉包 `@dcloudio/uni-h5-vue`（新版 `@dcloudio/uni-app` 的 dist 从 'vue' 导入内部标记 `isInSSRComponentSetup`，只存在于分叉包），报 `"isInSSRComponentSetup" is not exported by vue`。
- **最终版本铁律：项目 @dcloudio/* 全家桶精确锁 `3.0.0-alpha-4000120240201002` + vue/@vue/* 精确锁 `3.3.11` + vite `4.2.1` + pinia `2.0.36`（2.3 要 vue3.5 与 3.3 冲突）**。全部不带 ^。HBuilderX 里正常编译。升级 HBuilderX 后需同步升项目 @dcloudio/* 与 vue 生态（以 HBX plugins/uniapp-cli-vite/node_modules 里的版本为准）。
- 本地 CLI 构建为什么一直能过：uni:h5-resolve-id 插件把 `import from 'vue'` 重定向到 `@dcloudio/uni-h5-vue` 分叉；HBuilderX 老编译器对项目新版包不做此重定向才暴露问题。
- 历史第一轮坑（已被本轮覆盖，仅存档）：曾锁 vue 3.4.21 配新版 @dcloudio，本地能过但 HBX 编译报 `normalizeCssVarValue` 导出缺失（同样是 HBX 老编译器混用问题）。
- 技术栈：uni-app Vue3 + Vite 4.2.1（peer ^4.0.0）。仅实现 H5 端（dev:h5 / build:h5），manifest 已含 app-plus/mp-weixin 段，后续可扩展。
- ⚠️ 核心坑：`@dcloudio/vite-plugin-uni` 是 babel CJS 包，vite ESM 加载 config 时 `import uni from` 拿到的是整个 module.exports 对象（`uni is not a function` 且不报错消失，vite 静默吞掉导致所有 uni:* / vite:vue 插件全缺、.vue 无法编译报 "Install @vitejs/plugin-vue"）。修复：vite.config.js 显式 `import * as uniModule` + `uniModule.default` 调用。症状排查入口：configResolved 打印 plugin names。（vite4 下行为相同，此坑与版本无关）
- ⚠️ 第二坑：uni-app H5 项目根必须有 index.html（degit 模板没拉到时手动建），否则 dev server 根路径 404。
- 后端地址约定：**base URL 带 /api 前缀**（如 http://localhost:3000/api），request.js 拼接路径不带 /api。默认 `VITE_API_BASE_URL || 'http://localhost:3000/api'`。
- 可选后端实现：src/config/server.js（getBaseUrl/setBaseUrl/PRESET_SERVERS，持久化 uni storage key `iot_server_base_url`）+ 服务器设置页 pages/profile/server（自定义地址保存+测试连接、快捷选择、当前地址高亮）。后端 CORS 全开所以 H5 可直连任意后端。
