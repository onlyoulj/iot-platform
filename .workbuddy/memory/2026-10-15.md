## 设备远程控制面板（功能#1）
- 新表 `device_control_logs`（device_id, cmd_id, command, params, status, result, operator, created_at, acked_at，级联删除）。
- 新服务 `server/services/device-control.js`：sendCommand() 生成 cmd_id → 落库 sent → publishToDevice 发 `{type:'control', cmd_id, command, params, timestamp}` 到 downlink（MQTT 客户端优先/REST 兜底）→ 更新 delivered/failed；registerControlAck() 监听 uplink `{type:'control_ack', data:{cmd_id, code,...}}` 更新 success/failed + result + acked_at；sweepTimeout 每 60s 把 60s 未回执的 sent/delivered 标 timeout。
- 路由：`POST /api/devices/:id/command`（device:edit，operator 取 req.user.username）、`GET /api/devices/:id/commands`（device:view）。index.js 注册 registerControlAck()。
- 前端 Devices.vue 详情抽屉新增「远程控制」区块（v-if hasPermission('device:edit')）：5 个指令模板（reboot/sync_time/get_status/set_config/custom）+ 参数 JSON 编辑（前端 parseParams 校验）+ 离线设备禁用下发 + 指令历史列表（状态 tag/参数/回执 result），发送后 3s 轮询回执最多 10 次或全部终态即停，抽屉关闭停轮询。
- 端到端实测全通：下发 reboot topics=2（id+SN 双主题）→ 模拟设备 mqtt 发布 control_ack 到 device/8/uplink → 日志自动更新 status=success result={temperature:26.5,humidity:58} acked_at 落值。构建通过 + 截图验证（离线设备按钮置灰、提示、空态均正确）。
- 注意：后端不校验 params JSON 合法性（前端校验）；控制与 OTA 升级共用 downlink 通道，type 字段区分互不干扰。
